# Video Unicalizer

Пакетная уникализация видео: берёт папку роликов и делает из каждого столько
копий, сколько нужно. Копии отличаются и от оригинала, и друг от друга.
Все эффекты считаются за **один проход ffmpeg** — промежуточные файлы на диск
не пишутся, поэтому работает быстро.

| Что меняется | Как |
|---|---|
| Звук | сдвиг тона, случайный эквалайзер, спектральная обработка, микро-эхо, неслышимый ВЧ-тон |
| Картинка сверху | ваш PNG/JPG с любой прозрачностью, с медленным дрейфом |
| Скорость | ×2.1–2.2 (или любая другая), с сохранением высоты голоса или без |
| Зум | резкий рывок или плавный наезд в заданный момент таймлайна |
| Кадр | микро-кроп, микро-поворот, цвет, оттенок, зерно, виньетка, частота кадров |
| Файл | дата съёмки, марка и модель «камеры», тип контейнера, длина GOP, качество |

## Установка (Windows)

1. **Python 3.10 или новее** — https://python.org
   При установке обязательно галочка **Add Python to PATH**.
2. **ffmpeg** — https://www.gyan.dev/ffmpeg/builds/ (вариант *essentials*).
   Либо распакуйте и добавьте папку `bin` в PATH, либо положите `ffmpeg.exe`
   и `ffprobe.exe` в папку `bin` рядом с программой.
3. Библиотеки интерфейса:

```bash
pip install -r requirements.txt
```

Проверить, что ffmpeg на месте:

```bash
ffmpeg -version
```

Запуск — двойной клик по **`Запуск.bat`**.

## Установка (Mac)

Рядом лежит архив **`VideoUnicalizer-Mac.zip`**. Внутри исходники и скрипт,
который собирает нормальное `.app` двойным кликом. Подробности — в файле
`mac/ЧИТАТЬ ПЕРВЫМ (Mac).md` внутри архива.

## Как устроено окно

Слева меню из трёх страниц:

* **Запуск** — сюда перетаскиваете ролики, здесь же все настройки.
* **Очередь** — что сейчас обрабатывается, с прогрессом и логом.
* **Помощь** — полная инструкция прямо в программе, с таблицами и примерами.

На странице «Запуск» сверху то, что нужно всегда: файлы, пресет, число копий,
папка вывода и кнопка запуска. Ниже — **тонкая настройка**: шесть свёрнутых
разделов. В строке справа от названия раздела видно, что в нём сейчас включено,
поэтому открывать нужно только тот, который правите.

## Главное, что нужно понять

**Настройки задаются промежутком, а не числом.** Для каждой копии из промежутка
берётся своё случайное значение — поэтому десять копий одного ролика получаются
десятью разными файлами. Хотите зафиксировать значение — поставьте обе границы
одинаковыми.

**Время зумов считается по итоговому ролику.** Если исходник 60 секунд и стоит
×2, итог длится 30 секунд, и зум на 10-й секунде придётся ровно на середину.

**Сдвиг тона задаётся модулем**, направление выбирается случайно. Не опускайте
нижнюю границу к нулю: такие копии останутся вообще без сдвига.

## Пресеты

| Пресет | Когда брать |
|---|---|
| Лёгкая | Качество важнее всего, обработка почти незаметна. Ускорение выключено. |
| Средняя | Разумный баланс. С этого стоит начинать. |
| Жёсткая | Максимум непохожести. Обработку можно заметить, если приглядываться. |

Свои настройки сохраняются кнопкой **Сохранить пресет…** в файл `.json`,
который потом подхватывается и интерфейсом, и консольным режимом.

## Мелочи, которые экономят время

* **Настройки запоминаются.** Пресет, папка, число копий и все параметры
  сохраняются в `last_session.json` и подхватываются при следующем запуске.
* **Видно, сколько осталось.** В шапке идёт «3 из 12 • осталось ~4 мин 20 с»,
  посчитанное по реальной скорости текущей партии.
* **Упавшую задачу можно повторить.** Двойной клик по красной строке в
  очереди → кнопка «Повторить», перезапустится та же копия с тем же сидом.
* **Двойной клик по готовой** открывает файл в плеере.

## Скорость

На RTX 4060 Ti 30-секундный вертикальный ролик обрабатывается примерно за
4.5 секунды — это в 6.5 раз быстрее реального времени. Сотня таких роликов
пройдёт минут за восемь.

Полезно понимать: узкое место — не видеокарта, а фильтры на процессоре.
Чистое кодирование занимает около 2 секунд из этих 4.5, остальное — сдвиг
тона, спектралка и зерно. Поэтому разница между `nvenc` и `cpu` на коротких
роликах небольшая, а число параллельных задач важнее смены кодировщика.

Замер на партии из 8 копий тридцатисекундного ролика:

| Параллельных задач | Время | Копий в секунду |
|---|---|---|
| 1 | 35.9 с | 0.22 |
| 2 | 25.1 с | 0.32 |
| 4 | 19.9 с | 0.40 |

Отсюда дефолт: четверть от числа ядер, но не больше четырёх. На 16-ядерной
машине это 4 задачи, на 8-ядерной — 2. Выше четырёх прироста уже нет.

## Отчёты и повтор удачного варианта

Рядом с каждым готовым файлом ложится `.json` с сидом и **всеми** разыгранными
значениями: какая вышла скорость, где встали зумы, какие полосы эквалайзера
подмешаны.

Копия однозначно определяется парой «сид + настройки». Понравился вариант —
возьмите сид из отчёта:

```bash
python -m unicalizer.cli -i video.mp4 -o out --seed 123456789
```

## Консольный режим

Удобен для больших партий и запуска по расписанию.

```bash
python -m unicalizer.cli -i "C:\video" -o "C:\out" -n 5 --preset hard
```

| Ключ | Что делает |
|---|---|
| `-i` | файлы и/или папки (можно несколько) |
| `-o` | папка для результата |
| `-n` | копий из каждого файла |
| `--preset` | `light`, `medium`, `hard` |
| `--preset-file` | свой пресет `.json`, сохранённый из интерфейса |
| `--overlay` | картинка для наложения |
| `--opacity` | прозрачность оверлея, например `0.05` |
| `--speed` | фиксированное ускорение, например `2.15` |
| `--jobs` | параллельных задач |
| `--seed` | базовый сид для воспроизводимости |
| `--recursive` | искать видео и во вложенных папках |
| `--dry-run` | показать план, ничего не кодируя |

## Если что-то не так

**«Не найден ffmpeg»** — положите `ffmpeg.exe` и `ffprobe.exe` в папку `bin`
рядом с программой, это самый простой путь.

**Ошибка на конкретном файле** — двойной клик по строке в очереди покажет,
что именно сказал ffmpeg. Битые файлы и файлы без видеодорожки пропускаются
с пометкой в логе.

**Кодирует медленно** — кодировщик `auto` или `nvenc`, качество 24–26,
параллельных задач 1–2.

**Слышно обработку звука** — сдвиг тона до 0.2, сила спектралки до 0.05,
задержка эха до 4 мс.

**Видно оверлей** — непрозрачность выше 0.1 заметна на однотонных сценах.
