# Задание: собрать Video Unicalizer под macOS

Этот файл — для ИИ-агента (Claude Code), запущенного на Mac. Человек рядом
ждёт готовое приложение. Прочитай целиком до первой команды.

---

## Что это за проект

Пакетная уникализация видео: берёт ролики и делает из каждого N непохожих
копий (свой звук, длительность, кадр, метаданные). Всё считается за **один
вызов ffmpeg** на копию — промежуточных файлов нет.

Интерфейс на PySide6, движок на чистом Python + ffmpeg. Сторонних зависимостей
всего две: `PySide6` и `pillow`.

```
unicalizer/
    gui.py            окно: левое меню, страницы «Запуск / Очередь / Помощь»
    widgets.py        переключатели, двусторонние ползунки, аккордеоны
    theme.py          палитра и QSS
    ui_schema.py      описание всех 63 полей: подписи, границы, подсказки
    help_text.py      встроенная инструкция (HTML)
    params.py         параметры уникализации, 3 пресета, Roller (сид → числа)
    ffmpeg_builder.py сборка одной команды ffmpeg из параметров — ядро логики
    engine.py         очередь задач: потоки, прогресс, отмена, отчёты
    probe.py          поиск ffmpeg, чтение свойств видео, проверка NVENC
    config.py         память настроек между запусками
    cli.py            консольный режим
app.py                точка входа
unicalizer.spec       конфиг PyInstaller (уже настроен под macOS)
assets/icon.icns      иконка приложения, готова
```

## Что от тебя требуется

Собрать `Video Unicalizer.app` и убедиться, что он работает. Ничего
переписывать не нужно — код уже готов и на Windows проверен измерениями.

### Шаг 1. Зависимости

```bash
brew install ffmpeg
python3 --version   # нужен 3.10+
```

`ffmpeg` обязателен. В архиве его нет намеренно: собиралось всё на Windows,
там лежал только windows-бинарник, а для macOS нужен свой.

**Про `librubberband` можно не волноваться.** Им делается сдвиг высоты тона —
главный инструмент уникализации звука. Собран он не в каждом ffmpeg, и раньше
программа на такой сборке падала с `No such filter: 'rubberband'`. Теперь она
проверяет наличие фильтра и при отсутствии переключается на запасную цепочку
из встроенных фильтров (`asetrate` + `aresample` + `atempo`). Проверено
замером: тон получается тот же с точностью до долей герца, длительность
гуляет максимум на 23 мс. Ничего настраивать не нужно, но если хочешь знать,
что выбралось:

```bash
python -c "from unicalizer import probe; print('rubberband:', probe.filter_available('rubberband'))"
```

### Шаг 2. Сборка

```bash
cd <папка проекта>
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install PySide6 pillow pyinstaller
python -m PyInstaller --noconfirm --clean unicalizer.spec
```

Результат: `dist/Video Unicalizer.app`.

Готовый скрипт, делающий всё это, лежит рядом: `Собрать приложение.command`.
Можешь просто запустить его — но если что-то пойдёт не так, разбирайся
по шагам выше.

### Шаг 3. Проверка

Обязательно проверь, а не отчитывайся сразу:

```bash
open "dist/Video Unicalizer.app"
```

Что должно быть видно в окне:
- слева меню и **иконка-череп с ножницами** (не пустой квадрат);
- в левом нижнем углу — плашка про кодировщик; на Mac там будет
  «NVENC недоступен — кодирую на процессоре». **Это нормально**, см. ниже;
- шесть свёрнутых разделов с текстом-сводкой справа
  (`тон ±0.18–0.35 • эквалайзер 4 • спектралка • ВЧ-шум` и т.п.).

Затем прогони реальный файл. Возьми любой mp4 и:

```bash
source .venv/bin/activate
python -m unicalizer.cli -i /путь/к/video.mp4 -o /tmp/vu_test -n 2 --preset medium
ffprobe -v error -show_entries format=duration -of csv=p=0 /tmp/vu_test/*.mp4
```

Должно получиться два файла разного размера, длительность каждого ≈
исходная ÷ 2.15 (ускорение по умолчанию ×2.1–2.2).

## Что на Mac ведёт себя иначе — и это ожидаемо

**NVENC отсутствует.** Он есть только у видеокарт NVIDIA. `probe.nvenc_available()`
делает пробное кодирование, оно падает, функция возвращает `False`, и режим
`auto` уходит на процессор (libx264). Так и задумано, чинить нечего.

Скажи человеку прямо: **на Mac ставить кодировщик `cpu`**, а «Параллельных
задач» не поднимать выше числа ядер. Значение по умолчанию считается
автоматически (четверть ядер, максимум 4) — трогать его обычно не надо.

**Пути отличаются, и код это уже учитывает:**

| | Windows | macOS |
|---|---|---|
| готовые ролики | `~/Videos/Video Unicalizer` | `~/Movies/Video Unicalizer` |
| настройки | `%APPDATA%\VideoUnicalizer` | `~/Library/Application Support/VideoUnicalizer` |

Проверить, что разрешилось верно:

```bash
python -c "import sys; sys.frozen=True; from unicalizer.gui import default_output_dir; from unicalizer import config; print(default_output_dir()); print(config._path())"
```

**Gatekeeper.** Сборка без подписи Apple. При первом открытии macOS скажет,
что разработчик неизвестен. Обходится так: правый клик по приложению →
«Открыть» → в диалоге ещё раз «Открыть». Если приложение приехало по сети
и вообще отказывается запускаться:

```bash
xattr -dr com.apple.quarantine "dist/Video Unicalizer.app"
```

Подписывать и нотаризовать не надо, если человек не просил.

## Возможное улучшение (только если человек попросит)

На Mac есть аппаратное кодирование — **VideoToolbox**. Сейчас оно не
задействовано, `auto` уходит на процессор. Можно ускорить.

Проверь, доступно ли:

```bash
ffmpeg -hide_banner -f lavfi -i color=c=black:s=256x256:d=0.1 \
       -c:v h264_videotoolbox -frames:v 1 -f null - && echo ДОСТУПНО
```

Если да, трогать надо два места:

1. `probe.py` — рядом с `nvenc_available()` добавить такую же функцию
   `videotoolbox_available()` с пробным кодированием (скопируй логику,
   она уже правильная: проверяет реальным прогоном, а не списком кодеков).
2. `ffmpeg_builder.py`, функция `_encoder_args` (~строка 500) — там сейчас
   развилка `use_nvenc` / libx264. Добавить третью ветку:

```python
"-c:v", "h264_videotoolbox",
"-q:v", str(quality_to_vt),   # VideoToolbox не понимает -cq, у него своя шкала
"-profile:v", "high",
```

**Осторожно:** у VideoToolbox шкала качества своя — не CRF. Диапазон примерно
1–100, где больше — лучше (обратно CRF). Нужен пересчёт, а не подстановка.
И обязательно замерь, что стало быстрее: на Apple Silicon процессорный x264
работает очень бодро, и выигрыш может оказаться нулевым.

Я это менять не стал сознательно: проверить на Mac у меня возможности нет,
а отдавать непроверенный код в рабочий инструмент неправильно.

## Как здесь принято работать

Проект собран с проверкой измерениями, а не на глаз. Если будешь что-то
менять — держи ту же планку:

- **Не верь, что работает, пока не прогнал.** Каждое утверждение про звук,
  зум и прозрачность здесь подтверждено замером: сдвиг тона проверялся через
  FFT, зум — по яркости кадра с известной геометрией, прозрачность оверлея —
  сверкой с формулой смешивания.
- **Не ломай синхрон.** Скорость разыгрывается один раз и уходит и в видео,
  и в звук. Если добавишь фильтр, меняющий длительность только одной дорожки,
  на длинном ролике они разъедутся. Это уже была ошибка, её чинили.
- **Стороны кадра держи чётными.** libx264 не кодирует нечётный размер и
  падает; NVENC его прощает, поэтому баг легко не заметить. В коде есть
  `_even()`, применяется ко всем путям.
- **Интерфейс — PySide6, тёмная тема.** Человек забраковал tkinter словами
  «колхоз». Не предлагай его. Образец стиля — левое меню, градиентная главная
  кнопка, настройки в сворачиваемых разделах.
- **Язык интерфейса и общения — русский.**

## Если сборка падает

**`pip install PySide6` не ставится** — скорее всего macOS ниже 11. Тогда
приложение не собрать, но консольный режим работает:

```bash
pip install pillow
python3 -m unicalizer.cli -i ~/Movies/исходники -o ~/Movies/готовое -n 5 --preset medium
```

**PyInstaller ругается на отсутствующий модуль** — добавь его в
`hiddenimports` в `unicalizer.spec`.

**Приложение собралось, но при запуске сразу закрывается** — запусти
бинарник изнутри бандла, там будет видна ошибка:

```bash
"dist/Video Unicalizer.app/Contents/MacOS/Video Unicalizer"
```

**Пишет «Не найден ffmpeg»** — `brew install ffmpeg`, затем перезапусти.
Программа ищет ffmpeg сначала рядом с собой (папка `bin`), потом в PATH.
